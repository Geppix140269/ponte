# Baseline

What production is, for the parts of it no migration describes.

`supabase/migrations` says how production got here. This folder says what it
looks like now, for the tables that folder never mentions. Production holds 52
tables in `public`; the repository declares 23 of them, in `supabase/schema.sql`
and the dated migrations. The other 29 were created straight against the
database or pre-date the chain, and until 28 July 2026 nothing here said they
existed at all. That is the real reason applying this repository to an empty
project does not reproduce production, and the reason a Supabase preview branch
could never have worked.

## Nothing applies these files

They are outside `supabase/migrations` on purpose. No workflow reads this folder,
nothing runs on merge, and every object in
`2026-07-28-undeclared-production-tables.sql` already exists in production, so
there is nothing to apply there. Moving a file from here into the migration
chain needs a reconciliation plan and owner approval, as
`docs/codex/DATABASE-STATE.md` requires.

They are useful for two things:

- bringing a fresh project to the shape production is in;
- giving the next audit something to diff against, instead of a blank.

## Regenerate, do not hand-edit

Each file is generated by reading `pg_catalog`. Editing one by hand makes it say
what somebody believed rather than what production is, which is the failure this
folder exists to end. If a table changes, regenerate.

## What a baseline is not

It records what these tables **are**. It does not record why they exist, who
decided them, or whether they are still wanted, and it is not evidence that any
of them should survive. Several hold live rows. Deciding their future is a
separate piece of work, and a destructive one, so it needs its own plan.

## Files

- `2026-07-28-undeclared-production-tables.sql` — the 29 tables with no
  repository provenance: 272 columns, 101 constraints, 68 indexes, 38 RLS
  policies. Includes the shop-era tables `products`, `categories`,
  `bundle_items`, `orders`, `order_items` and `order_notes`, which
  `supabase/schema.sql` describes as dropped; the file that would drop them,
  `supabase/pending/20260722a_drop_legacy_shop.sql`, has never run.
