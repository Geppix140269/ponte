# Persistent navigation & unsaved-work protection — route-by-route audit

**Date:** 2026-07-30
**Scope:** Every user-facing route under `app/[locale]/`, plus the shared chrome
that frames them.
**Trigger:** Development brief "Persistent Navigation and Unsaved-Work
Protection" issued 2026-07-30.
**Status of this document:** Audit only. **No code has changed.** No Launch Mode
classification has been made by the owner yet, and no design authority for a
shared Back control or an unsaved-changes dialog exists. See §5.

This is the read-only audit the brief requires before implementation. It records
what is true today so the owner can classify the work and authorise (or defer)
it under Launch Mode and the Design Constitution.

## 1. How the chrome works today

Two shell systems already supply a **persistent, clickable, home-linked logo
with an accessible label** on essentially every route. Requirement 1 of the
brief (persistent brand navigation) is therefore *largely already met
structurally*; the real gaps are Back controls (req 2/3), unsaved-work
protection (req 4) and error-state recovery (req 7).

- **Legacy obsidian chrome** — `app/[locale]/layout.tsx` wraps everything in
  `components/ChromeGate.tsx`, which renders `components/SiteHeader.tsx`
  (`<Link href="/"><Logo/></Link>`, `aria-label` from `nav.homeAriaLabel`) on
  every route **except** a bared allowlist.
- **Brand v5 heritage-light chrome** — bared routes render their own light
  chrome via `components/shell/PonteShell.tsx`, `components/desk/DeskShell.tsx`,
  `components/find/FindChrome.tsx` or `components/legal/LegalPage.tsx`. All use
  `components/ponte/brand/PonteLockup.tsx`, which links home with
  `aria-label="Ponte Trade, home"`.

**Consequence:** a home route is always one click away. What is *not* consistent
is an explicit **Back** to the previous logical step, and there is **no
unsaved-work protection anywhere in the repository.**

### Existing infrastructure to reuse (do not rebuild)

- `lib/structure/draft.ts` — pure client draft model for the Structure composer.
- `lib/structure/resume.ts` — rebuilds a draft from a saved listing row
  (`draftFromRow`); **drafts are persisted as listing rows with `draft:true`**,
  no shadow store.
- `components/structure/ClassifyStep.tsx` — contains `DiscardWarning`, an inline
  confirm shown only when a classification change would destroy real work, with
  the safe action ("Keep") focused by default. **This is the only explicit
  unsaved-work confirmation in the app today**, and it is the natural design
  precedent for requirement 4.
- `components/ListingForm.tsx` — its own `useState` model; a properly **labelled**
  "Back" button (with `ArrowLeft` + visible text); a `sessionStorage` stash
  (`ponte_draft`) for the guest sign-in round-trip (text only, files lost).
- `components/products/intake/ProductIntake.tsx` — auto-saves the full session to
  `sessionStorage` on every change and rehydrates with a "we brought you back"
  banner (document bytes not persisted).

## 3. Findings, ranked

### F1 — No unsaved-work protection exists anywhere (brief §4). *Universal gap.*
No `beforeunload`, no route-change interception, no dirty-state guard in the
entire repository. The single exception is `ClassifyStep`'s inline
`DiscardWarning` for one classification change. Highest real-loss surfaces:
`/deal-rooms/propose`, `/deal-rooms/.../admission` (authority declaration),
Deal Room blockers/evidence/clarification, `/admin/listings`,
`/admin/verifications`, `/structure`, `/marketplace/new`.

### F2 — Two composers use icon-only Back controls (brief §2/§3). *Clear violation.*
`StructureComposer` (chevron SVG, `aria-label` only) and `CheckComposer`
(chevron SVG, hard-coded `aria-label="Back"`, not even i18n) present an
icon-only arrow with no visible text label — exactly what req 3 forbids.
`ListingForm` is the correct counter-example ("Back" + arrow).

### F3 — Back controls are inconsistent and absent on many journey pages (§2/§8).
No shared journey-navigation component. Where Back exists it is a breadcrumb
link, a "Back to the room/workspace" `Action`, or an icon — never one
consistent, labelled control. Notable *missing* Back: `/find/o/[ref]` (inert
breadcrumb while holding an introduction composer), Deal Room `activity` and
the workspace hub (siblings have Back, these do not), every admin decision page,
`/deal-rooms/propose` and `/deal-rooms/.../admission` (both heavy forms).

### F4 — No branded error boundaries (brief §7). *Dead-end risk.*
Absence of `error.tsx`/`global-error.tsx` means an unhandled error yields Next's
default page with no logo, no Back, no recovery — the dead-end the brief
explicitly prohibits.

### F5 — Draft support is real but partial and inconsistent (brief §5/§6).
Three different mechanisms (listing-row drafts, two separate `sessionStorage`
stashes) and none shared. `/structure` only exposes "Save draft" at the final
step; `CheckComposer` and `VerifyForm` have none (low loss). Anonymous-user
messaging (§6) is honest where it exists (intro/investigate composers state work
is preserved across sign-in) but there is no consistent "Sign in to save"
pattern.

### F6 — Minor: double `<main>` landmark on `/learn/*`.
`/learn/duties` and `/learn/trade-data` are not bared, so `ChromeGate` wraps
them in `<main>` and each page renders its own `<main>` — two landmarks
(accessibility defect, brief §9). They read as unmigrated legacy routes.

### F7 — Minor: `/not-found.tsx` second CTA labelled "Browse the Catalogue" points at `/pricing`.

## 4. What is already compliant (do not touch)

- Persistent, labelled, keyboard-reachable home logo across all shells (req 1).
- Logical (not `history.back()`) back within composers — no `router.back()` /
  `history.back()` anywhere in `app/` (req 3).
- State preservation *within* a composer's own step navigation, and across the
  sign-in gate for Structure/Investigate/Introduction (req 3, partial §6).
- Listing-row draft persistence + resume for the Structure journey (req 5).
- Good empty/error recovery on the market-signals subtree and the not-found
  pages (req 7, partial).

## 5. Governance position (must be resolved before implementation)

This brief is **substantial work spanning every route** → per `AGENTS.md` it
requires an ExecPlan (`.agent/PLANS.md`) before implementation, and it hits
three explicit **stop conditions**:

1. **Launch Mode classification.** By the mandatory decision test, most of this
   brief is a UX-quality/robustness improvement and classifies as
   **Post-Launch**, *unless the owner promotes specific items*. A defensible
   Launch-Blocker candidate is **F1 for the highest-loss Deal Room surfaces**
   (silent loss of an authority declaration / admission data mid-journey can
   stop a member safely completing the PROGRESS journey). Owner must classify.
2. **Design Constitution.** A shared **Back control** and an **unsaved-changes
   dialog** are new interaction patterns. The Constitution appears silent on
   them → the rule is *stop and request owner approval; do not improvise a
   generic substitute*. The existing `DiscardWarning` (ClassifyStep) is the
   natural approved precedent to extend rather than invent anew.
3. **Beyond the approved milestone.** The active milestone is market
   discoverability / Deal Room, not navigation. Implementing this brief now
   needs explicit owner authorisation.

**Recommendation:** deliver this audit; have the owner (a) classify F1's
Deal-Room slice as Launch Blocker or Post-Launch, (b) approve extending the
`DiscardWarning` precedent into a shared unsaved-work guard + a shared labelled
journey-Back component, or hold for design authority, and (c) confirm the
anonymous-draft policy for §6. Then open a scoped ExecPlan and deliver
journey-by-journey PRs with desktop + 390×844 evidence, per the Constitution's
delivery discipline.

## 6. Proposed implementation shape (subject to §5 approval)

1. `useUnsavedChangesGuard(isDirty)` hook — one `beforeunload` listener + an
   in-app navigation intercept — plus a shared `UnsavedChangesDialog` built from
   the `DiscardWarning` precedent (title "You have unsaved changes"; actions
   "Continue editing" [safe, default/focused], "Save as draft", "Leave without
   saving"; focus trap; return focus on close).
2. A shared `JourneyBack` component (visible label, optional leading arrow,
   keyboard + focus states, min touch target) to replace the two icon-only
   chevrons and fill the missing-Back pages, wired to each journey's logical
   previous step (never blind history).
3. Branded `error.tsx` (per subtree or root) + `global-error.tsx` with logo +
   "Try again" + "Return to Ponte Trade".
4. Reuse existing draft persistence; expose "Save as draft" earlier in
   `/structure`; add honest "Sign in to save" for anonymous per §6.
5. Fix F6 (double `<main>`) and F7 (not-found CTA) as they are touched.
6. Automated tests for navigation, state retention and unsaved-change
   interception; desktop + 390×844 evidence per journey.
