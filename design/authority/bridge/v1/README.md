# Ponte Bridge System v1

**Status:** APPROVED — AUTHORITATIVE  
**Owner:** Giuseppe Funaro  
**Approval date:** 27 July 2026

This directory is the canonical production authority for Ponte's bridge interaction language.

## Scope

It governs:

- Ponte Family Bridge
- Ponte Action Bridge
- Task Completion Bridge
- Commercial Journey Bridge
- Counterparty Connection
- Multi-party Deal Room Bridge
- compact journey header
- mobile bridge behaviour
- reduced-motion bridge behaviour
- the gold italic treatment in the landing headline

## Binding boundaries

This package changes visual and interaction treatment only within its approved scope. It does not authorise replacement of production navigation, authentication, routes, data, permissions or business logic.

The production header must preserve the approved destinations and session-aware account control. The landing implementation must preserve real Market Signals, real actions and their existing destinations.

## Implementation law

- The bridge organises the interaction; it is not decoration around generic cards.
- The moving signal and selected destination use the approved gold token.
- Gold is never a review, approval, warning or verification status.
- Progress never displays 0%.
- Before meaningful action, no percentage is shown.
- Completion is deterministic, weighted and irregular.
- Commercial stage uses named milestones and remains distinct from completion.
- Two-action and three-action variants must both look intentional.
- Keyboard, focus, mobile and reduced-motion behaviour are required.
- No contributor may substitute cards, tabs or a generic stepper.

## Source package

The owner-approved source package was delivered as `Ponte_Bridge_Implementation_Handoff_v1`. Its implementation sources are preserved under this directory. Reference renders are approval evidence; production code must use the sources and tokens rather than rasterising screenshots.

## Change control

Changes require:

1. a written proposal identifying the affected rule;
2. explicit approval by Giuseppe Funaro;
3. a versioned amendment to `design/authority/PONTE_DESIGN_CONSTITUTION_v1.md` or a superseding version;
4. updated desktop, mobile and reduced-motion references;
5. an accepted ADR where the authority or system boundary changes.

A local implementation need is not permission to modify the system.
